# Архитектура локального просмотра — RU 1.45

Мод разработан с нуля по исходникам клиента `wot-src-ru`, ветка `mt-ru`,
коммит `838c2b2b`, версия 1.45 #2268. Испытательный клиент: RU 1.45 #2269.
Существующие реализации просмотрщиков не использовались как образец.

## Геометрия и жизненный цикл

Каталог строится из `ArenaType.g_cache`, группируется по `geometryName`.
Каждая строка содержит только режимы этой карты, включая `explicitRequestOnly`.
Исключается геометрия без установленного `space.settings`. Для отсутствующих
названий используются geometryName/gameplayName.

`LocalSession` сохраняет Account, выбранный танк, параметры окружения ангара,
FOV, курсор и состояние оптимизации lobby UI. Штатный `HangarSpace.destroy()`
освобождает ангар перед созданием локального мира. Затем `createSpace()` и
`addSpaceGeometryMapping()` загружают геометрию с маской выбранного режима из
`SpaceVisibilityFlagsFactory`. `BigWorld.FreeCamera` отображает этот мир;
собственный контроллер задаёт матрицу камеры для полёта по шести направлениям.

Выход выполняет обратные действия через `CleanupStack`. Ошибка одного шага
не отменяет остальные шаги. После удаления только собственного пространства
`HangarSpace.init()` возвращает штатный ангар и его танк. Новый запуск блокируется,
пока ангар и модель танка не готовы. Журнал фиксирует совпадение Account,
танка, пути ангара, окружения и маски видимости. ID заново созданного пространства
может отличаться.

Серверный бой, тренировочная комната и Avatar не создаются. Мод не вызывает
`clearEntitiesAndSpaces`, не подменяет `BigWorld.player()` и не меняет текущий
танк. Исходные файлы игры не заменяются; архив добавляет ресурсы под своими именами.

## Штатный UI

Окно выбора — собственные `wotstatLocalMapsSelector.swf` / `MapSelector`
и Python `Selector(AbstractWindowView)`. Содержимое создаётся один раз в `onPopulate`,
до первого показа: слева список, справа название, режим и превью, снизу кнопки.
После `as_setData` содержимое становится видимым сразу, без пустого кадра рамки.
`TrainingWindow` и `trainingWindow.swf` не используются, отложенного изменения
чужого окна нет. Рамка и нижняя панель — оригинальный `Window`, элементы —
`ScrollingList`, `DropdownMenuUI`, `DropDownListItemRendererSound`, `ButtonNormal`.
Dropdown автоматически рассчитывает высоту по числу режимов
(`menuRowsFixed=false`, `rowCount=-1`). Кнопки заканчиваются на нижней границе
содержимого; фон нижней панели и внешние отступы задаёт `Window`.

Превью — оригинальный `LobbyMinimap` / `MinimapLobby` с локальным Python
наследником: при отсутствии PNG он использует установленный mmap.dds либо
оставляет изображение пустым. Компонент регистрируется под собственным alias;
его размер передаётся вместе с картой, чтобы координаты значков совпадали.
Невидимый `MapBridge` сохраняет обработку жизненного цикла lobby app и через
штатный `LoaderManager` загружает `MinimapLobby.swf` перед первым открытием.
Он больше не ищет и не перестраивает окно на сцене.

Для просмотра создаётся оригинальный `battle.swf` через `GUI.Flash`. Класс
`LocalBattleApp` использует инициализацию и менеджеры `BattleEntry`/`AppEntry`.
Локальная копия Python-функции инициализации меняет только фабрику `MainWindow`
в её собственном словаре globals на адаптер Flash-корня. Глобальный класс
`MainWindow` остаётся прежним. Второй Wulf `MAIN_WINDOW` не создаётся, поскольку
в RU 1.45 он конфликтует с общими областями основного окна. Не создаётся
`BattleGameInputMgr`, которому нужен Avatar.

Боевые SWC используются компилятором только как внешние зависимости. В трёх
собственных SWF нет копий игровых классов или нарисованной заново миникарты.
Боевой и ангарный адаптеры разделены: нативные AS3 классы клиента привязаны
к соответствующему корневому movie.

HUD подключает оригинальный `minimapUI` / `Minimap`, `GUI.MinimapFlashAS3`,
штатный атлас, сетку и библиотеку значков. Значки баз и нейтральных точек берутся
из `ArenaType`; камера показана оригинальным `VideoCameraEntry`.

В 1.3.0 HUD также создаёт штатные `BackButtonUI`, `Slider`, `CheckBox`,
`DropdownMenuUI` и `ScrollBar`. В боевом movie отсутствует реализация части
ангарных контролов: `native_library.codeLibrary` читает установленный `lobby.swf`
через `ResMgr`, оставляет в памяти только `FileAttributes` и `DoABC` и формирует
библиотеку без привязки корневого `LobbyApplication`. `NativeLobbyLibrary`
загружает её через `Loader.loadBytes` в домен локального movie, затем подключает
штатные символы `guiControlsLobby.swf`. Исходный ресурс остаётся неизменным;
игровой код не записывается на диск и не включается в архив мода.

`debug_panel.SettingsRegistry` хранит секции и значения между просмотрами.
HUD подписывается на изменения после готовности и отписывается при уничтожении.
Изменение значения обновляет один контрол; добавление или удаление секции
перестраивает панель в следующем callback. Ошибки обработчиков изолированы.
Контракты и пример регистрации: [debug-panel-api.md](debug-panel-api.md).

Удержание любого Ctrl переводит локальный battle app в `GUI_ENABLED`,
останавливает камеру и включает кнопки панели. Отпускание обоих Ctrl возвращает
`CURSOR_ATTACHED`. Потеря фокуса сбрасывает удержанные клавиши. Отключение ввода
закрывает dropdown и завершает перетаскивание штатных контролов. Меню сохраняет
собственный режим паузы независимо от Ctrl. Медленное движение назначено на C.
HUD слушает `StageResizeEvent` и пересчитывает положение шапки, панели и миникарты
при изменении разрешения или масштаба интерфейса. Список выбирает направление
раскрытия по доступному месту; длинные списки используют штатную прокрутку.
Перед перестроением секций и отключением ввода `AbstractView.setFocus(this)`
переносит фокус на HUD и обновляет запомненный элемент для следующего открытия
меню. Поэтому удалённый контрол не остаётся в истории фокуса. При открытом
модальном окне его текущий фокус сохраняется по контракту `AbstractView`.

Esc открывает модальный `ingameMenu.swf` в TOP_WINDOW с исходными canClose=False,
canDrag=False. Настройки — исходный `SettingsWindow`; кнопки выхода и возврата
обслуживает локальная сессия. Help отсутствует в штатном списке кнопок. На время просмотра
штатные common business handlers направляют подтверждения и дочерние окна
на локальное battle app. Их прежние назначения восстанавливаются при выходе.

`LoadingCover` наследует штатный `WaitingTransition` (`waitingTransitionsApp.swf`).
Его независимый Flash root переживает закрытие обоих приложений. Чёрный фон и
оригинальная шестерёнка выводятся перед тяжёлой операцией: callback запускается
через 0,15 с после DAAPI afterCreate. Независимый таймаут отменяет переход, если
инициализация экрана не завершилась. При смене Account/app cleanup синхронный.

`LocalArenaBorder` использует штатный `ArenaBorderController` с ID локального
пространства вместо Avatar.spaceID. Рендер выполняет `ArenaBorderHelper`;
сохраняются игровые настройки, цвета, затухание, обработка Alt и изменения настроек.

## Совместимость с UDO

Штатный `SoundZoneTrigger.__init__` создаёт CGF объект в `player().spaceID`,
который у Account равен 0. Для этого конструктора используется локальная копия
функции с CGF фасадом: во время просмотра недействительный ID 0 заменяется
ID локального пространства. Остальные операции CGF и глобальные модули
не подменяются.

## Основные клиентские контракты

- `gui/ClientHangarSpace.py`, `gui/shared/utils/HangarSpace.py`: загрузка,
  освобождение и восстановление ангара, публичные environment/visibilityMask.
- `helpers/OfflineMode.py`: клиентское пространство и `FreeCamera`.
- `gui/Scaleform/framework/application.py`, `battle_entry.py`: корень movie,
  жизненный цикл DAAPI, штатные менеджеры и библиотеки.
- `AbstractWindowView`, `Window`, `ScrollingList`, `DropdownMenu`,
  `LoaderManager`, `MinimapPresentation` и `MinimapLobby`: базовое окно,
  контролы, загрузка штатной библиотеки и превью.
- `gui/Scaleform/daapi/view/battle/shared/minimap/component.py`: нативная
  миникарта, координаты и entry API.
- `story_mode/gui/scaleform/daapi/view/battle/minimap.py`: полные границы
  квадратной текстуры для прямоугольных карт (`StoryModeMinimapComponent`).
  `minimap_bounds.py` использует длинную сторону исходной границы для обеих осей.
  Мировая граница и точка появления камеры используют исходный игровой прямоугольник.
- `gui/Scaleform/daapi/view/common/settings/SettingsWindow.py` и
  `framework/package_layout.py`: настройки, дочерние окна и подтверждения.

Проверенные сценарии и ограничения перечислены отдельно в отчёте испытаний.
